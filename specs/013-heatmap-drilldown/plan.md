# Implementation Plan: Heatmap Day Drill-Down

**Branch**: `013-heatmap-drilldown` | **Date**: 2026-04-10 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/013-heatmap-drilldown/spec.md` (GitHub Issue #4)

## Summary

Make the contribution heatmap interactive. Each of the 7 heatmap rows becomes a clickable item (`kind="day"`) mapped to the most recent date in that row. Pressing `<CR>` opens a day drill-down popup listing all events for that date. Works in both the dashboard (own heatmap) and the watched user profile popup.

## Technical Context

**Language/Version**: Lua (LuaJIT 2.1), Neovim 0.12.0-dev  
**Primary Dependencies**: `gh` CLI v2.45.0, `vim.system()` async, `nvim_open_win` floating windows

**Performance Goals**: Popup opens immediately; events render within 3 seconds  
**Constraints**: One item per heatmap row (line-based routing, not column-based); `render_heatmap` backwards-compatible (nil `items` = no change)

### Changes to `lua/alex/gh_heatmap.lua`

Extend `render_heatmap` to optionally populate a `items` table with `kind="day"` entries. The change is confined to the inner render loop — track the last seen date per row, insert items after lines are added:

```lua
M.render_heatmap = function(lines, hl_specs, contrib, items, username)
  -- ... existing guard/setup ...
  local day_last_dates = {}  -- day_idx → most recent date in that row

  for day_idx = 1, 7 do
    local last_date = nil
    -- ... existing row_chars / col_positions loop ...
    -- inside the week loop: if day.date then last_date = day.date end
    day_last_dates[day_idx] = last_date
    -- ... table.insert(heatmap_lines/heatmap_hl) ...
  end

  local base_line = #lines
  for i, row in ipairs(heatmap_lines) do
    table.insert(lines, row)
    -- ... existing highlights ...
    if items and username and day_last_dates[i] then
      table.insert(items, { line = base_line + i - 1, kind = "day",
                            date = day_last_dates[i], username = username })
    end
  end
  -- ... total_line + separator unchanged ...
end
```

Callers that omit `items`/`username` are unaffected.

**`M.open`**: add `popup_items` closure and `<CR>` handler:
```lua
local popup_items = {}
bmap("<CR>", function()
  local cur_line = vim.api.nvim_win_get_cursor(win)[1] - 1
  for _, item in ipairs(popup_items) do
    if item.line == cur_line and item.kind == "day" then
      require("alex.gh_day_activity").open(item.username, item.date)
      return
    end
  end
end)
```

4. Watched user profile popup → cursor on heatmap rows → `<CR>` → day popup for that user
5. Day popup `q`/`<Esc>` closes cleanly
